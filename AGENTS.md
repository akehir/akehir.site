# Agentic Development Guide

This document provides essential context and instructions for LLM agents working on this repository.

## Project Context

- **Project Name**: Akehir.com
- **Framework**: Angular (v21+)
- **Styling**: Tailwind CSS, Sass
- **Key Features**:
  - WebGL Fluid Animation (background)
  - Integrated Console for application control
  - Progressive Web App (PWA) support
- **Main Goal**: A personal website with high interactivity and a unique user interface.

## Codebase Navigation

- `src/app/core/`: Singleton services, interceptors, guards, and core models.
- `src/app/layout/`: Reusable UI components such as navigation bars, footers, and layout wrappers.
- `src/app/pages/`: Feature-specific components and page-level logic.
- `src/app/app-routing.module.ts`: Central routing configuration.
- `src/assets/`: Static assets like images and icons.
- `src/stylesheets/`: Global styles and SCSS files.
- `tools/`: Node scripts that generate committed files (RSS feed in `src/assets/rss.xml`, sitemap in `src/assets/sitemap.xml`, prerender routes in `src/prerender-routes.txt`, search index in `src/assets/search-index.json`).

## Development Workflow

Agents should follow these steps when making changes:

1.  **Analyze**: Understand the existing code and its impact.
2.  **Implement**: Apply changes following established patterns.
3.  **Lint & Format**: Run `npm run lint` to ensure code quality and style consistency. If formatting issues are found, use `npm run lint:fix` (Prettier). After completing a task, always run `npm run lint` to ensure no new issues were introduced.
4.  **Test**: Run `npm test` to verify that changes do not break existing functionality.
5.  **Verify**: For UI changes, consider the impact on responsiveness and accessibility.

## Coding Conventions

- **Angular**: Follow standard Angular component, service, and module patterns. Use standalone components where appropriate (if already adopted in the codebase).
- **Styling**: Use **Tailwind CSS** utility classes for styling whenever possible. For complex or global styles, use SCSS in the appropriate files.
- **Naming**:
  - Components: `name.component.ts`
  - Services: `name.service.ts`
  - Modules: `name.module.ts`
  - Interfaces/Models: `name.model.ts`
- **TypeScript**: Use strict typing. Avoid `any` unless absolutely necessary.
- **Comments**: Do NOT add comments unless explicitly requested.

## Blog Post Workflow

To create a new blog post, follow these steps:

1.  **Create Markdown Content**: Write the blog post in Markdown and save it to `src/assets/blog/<year>/<slug>.md`. The first line of the file is the `# Title` and is rendered into the entry (replacing the projected title in `BlogEntryComponent`), so keep it in sync with the `title` metadata.
2.  **Generate Component**: Create a new Angular component for the blog entry in `src/app/pages/blog/entries/<year>/<slug>.component.ts`. Use the existing pattern (e.g., importing `BlogEntryContainerComponent`).
3.  **Register Entry**: Add a new entry to the `blogEntries` array in `src/app/pages/blog/blog.module.ts`. Ensure all required metadata (title, author, categories, mainCategory, publishedDate, modifiedDate, routerLink, content, source) is provided.
4.  **Update RSS Feed**: Regenerate the RSS feed by running `node tools/generate-rss-feed.mjs` (see [RSS Feed & Sitemap](#rss-feed--sitemap)).
5.  **Update Sitemap**: Regenerate `src/assets/sitemap.xml` by running `node tools/generate-sitemap.mjs` (see [Sitemap](#sitemap)).
6.  **Update Prerender Routes**: Regenerate `src/prerender-routes.txt` by running `node tools/generate-prerender-routes.mjs` (see [Prerender Routes](#prerender-routes)).
7.  **Update Search Index**: Regenerate `src/assets/search-index.json` by running `node tools/generate-search-index.mjs` (see [Search Index](#search-index)).

## RSS Feed & Sitemap

The RSS feed lives in `src/assets/rss.xml`, next to the sitemap, and is served at `https://akehir.com/assets/rss.xml`. It lists all non-hidden blog entries in reverse chronological order and inlines the full Markdown content of each entry (as CDATA in `<description>`).

- **Generated file, do not edit by hand.** `src/assets/rss.xml` is generated by `tools/generate-rss-feed.mjs` from the `blogEntries` array in `src/app/pages/blog/blog.module.ts` plus each entry's Markdown content file. Always regenerate it after adding, modifying, or hiding a blog entry (including `modifiedDate` changes, which update the per-item `lastBuildDate` and the channel's `lastBuildDate`).
- **Regenerate**: `node tools/generate-rss-feed.mjs`
- **Verify without writing**: `node tools/generate-rss-feed.mjs --check` (fails if `rss.xml` is out of date).
- **Sitemap cross-check**: Running the generator also verifies `src/assets/sitemap.xml` and exits non-zero when a non-hidden blog URL or static route is missing, when a blog URL in the sitemap has no matching entry, or when URLs are duplicated. Fix the sitemap if the check fails. Keep the sitemap in sync whenever routes or blog entries change.
- **Feed links**: The feed is linked from `src/index.html` (`<link rel="alternate" type="application/rss+xml">` in the `<head>`), from the blog entries page (the "RSS Feed" link in `src/app/pages/blog/entries.component.html`), and from the Resources section of `src/llms.txt`. If the feed location changes, update all of these.

## Search Index

`src/assets/search-index.json` is the committed index for the client-side blog search (`/blog/search` and the inline search on `/blog`). It contains one record per non-hidden blog entry (`slug`, `title`, `author`, `mainCategory`, `categories`, `publishedDate`, `modifiedDate`, `routerLink`, and `content` — the entry's Markdown converted to plain text) and is consumed by `SearchIndexService` (`src/app/pages/blog/search/search-index.service.ts`) in the shared `BlogSearchComponent` (`src/app/pages/blog/search/search.component.ts`).

- **Generated file, do not edit by hand.** `src/assets/search-index.json` is generated by `tools/generate-search-index.mjs` from the `blogEntries` array in `src/app/pages/blog/blog.module.ts` plus each entry's Markdown content file (plain text via the existing `marked` dependency; hidden entries are excluded, consistent with RSS/sitemap).
- **Regenerate**: `node tools/generate-search-index.mjs`
- **Verify without writing**: `node tools/generate-search-index.mjs --check` (fails if `search-index.json` is out of date).
- **When to regenerate**: After adding, removing, renaming, or hiding any blog entry, or changing an entry's text, metadata, or `routerLink`. Search state is deep-linkable via query params on `/blog` and `/blog/search` (`?q=&cat=&group=&author=&from=&to=&sort=`).
- **Adding a static blog page** (like `/blog/search` itself): the sitemap and prerender-routes generators also collect static child routes from the `children` list in `blog.module.ts` (skipping the empty path and the blog entry paths), and the RSS generator's sitemap cross-check allows them — no manual sitemap edits needed.

## Sitemap

`src/assets/sitemap.xml` is the XML sitemap of the site, served at `https://akehir.com/assets/sitemap.xml`. It is listed in `src/robots.txt` (the `Sitemap:` directive) and in the Resources section of `src/llms.txt`; if the sitemap location changes, update both.

- **Generated file, do not edit by hand.** `src/assets/sitemap.xml` is generated by `tools/generate-sitemap.mjs` from the Angular routing table and the data that backs the parameterized routes — the same sources as `src/prerender-routes.txt`, so the sitemap always lists exactly the routes the site serves:
  - `/` and the static pages from `src/app/app-routing.module.ts` (including nested `children`), in routing-table order.
  - All non-hidden blog entries from `src/app/pages/blog/blog.module.ts` (hidden entries are skipped), listed after `/blog` with the most recently modified entry first. Their `<lastmod>` is the entry's `modifiedDate` (or `publishedDate` as fallback) as `YYYY-MM-DDT09:09:09+01:00`.
  - Static child pages of the blog module from the `children` list in `src/app/pages/blog/blog.module.ts` (e.g. `/blog/search`), listed before the blog entries. The empty child path (`/blog` itself) and the blog entry paths are skipped.
  - Every project in `src/app/core/data/ProjectList.ts` (`/projects/<id>`), listed after `/projects` in sorted order.
  - Every colour demo variant in `src/app/core/services/colour.service.ts` (`/demos/colour/<variant>`), listed after `/demos/colour` in sorted order.
- **Error routes are excluded**: `/error` and its children (`/error/403`, `/error/404`, `/error/500`) are part of the routing table but are catch-all pages for failed navigation and must not be submitted to search engines, so the generator skips them. (The RSS generator's sitemap cross-check in `tools/generate-rss-feed.mjs` is aligned with this and does not require them.)
- **Priorities**: Top-level pages and blog entries get `1.0`, one level deeper (project detail pages, colour demo variants) get `0.8`, and the legal pages `/privacy` and `/imprint` get `0.1`. Only blog entries carry a `<lastmod>`; the routing table has no date source for the other routes.
- **Regenerate**: `node tools/generate-sitemap.mjs`
- **Verify without writing**: `node tools/generate-sitemap.mjs --check` (fails if `src/assets/sitemap.xml` is out of date). Running `node tools/generate-rss-feed.mjs` additionally cross-checks the sitemap against the blog entries and the static routes (missing or duplicated URLs fail the run).
- **When to regenerate**: After adding, removing, renaming, or hiding any blog entry (including `modifiedDate` changes), adding or removing a project, adding a colour demo variant, or changing the static routing in `app-routing.module.ts`.

## Prerender Routes

`src/prerender-routes.txt` lists every route that the Angular builder should prerender (SSG). It is the input for the `prerender.routesFile` option in `angular.json` and is consumed when a production build runs with prerendering enabled.

- **Generated file, do not edit by hand.** `src/prerender-routes.txt` is generated by `tools/generate-prerender-routes.mjs`. The routes are collected from the same sources the site is built from, so the file stays in sync automatically:
  - Static pages from `src/app/app-routing.module.ts` (including nested `children`, e.g. `/error/403`).
  - All non-hidden blog entries from `src/app/pages/blog/blog.module.ts` (hidden entries are skipped).
  - Static child pages of the blog module from the `children` list in `src/app/pages/blog/blog.module.ts` (e.g. `/blog/search`). The empty child path (`/blog` itself) and the blog entry paths are skipped.
  - Every project in `src/app/core/data/ProjectList.ts` (`/projects/<id>`).
  - Every colour demo variant in `src/app/core/services/colour.service.ts` (`/demos/colour/<variant>`).
- **File format**: One route per line, in sorted order, with **no comments and no empty lines**. The builder treats every line of `routesFile` as a route, so never add comments or blank lines by hand — doing so would corrupt the build. This is why the file is generated rather than maintained manually.
- **Regenerate**: `node tools/generate-prerender-routes.mjs`
- **Verify without writing**: `node tools/generate-prerender-routes.mjs --check` (fails if `src/prerender-routes.txt` is out of date).
- **When to regenerate**: After adding, removing, renaming, or hiding any blog entry, adding or removing a project, adding a colour demo variant, or changing the static routing in `app-routing.module.ts`.
- **Prerendering is opt-in at build time**: The route file is only read by the builder when prerendering is enabled. To prerender in a production build, enable `prerender` (pointing `routesFile` at `src/prerender-routes.txt`) in `angular.json`. This currently requires an `ssr`/`server` entry for the `@angular/build:application` builder, which is not yet configured in this project — until then the file is a ready-to-use, verified source of truth for the routes to prerender.
