## 2. Search model (pure, no Angular)

- [ ] 2.1 Create `src/app/pages/blog/blog-search.model.ts` with: `BlogSearchCriteria` interface (`query: string`, `categories: EntryCategory[]`, `fromDate: string | null`, `toDate: string | null`, `sort: 'newest' | 'oldest'`), `BlogSearchResult` view model (`title`, `routerLink`, `publishedDate`, `mainCategory`, `matchedCategories: EntryCategory[]` — deliberately no `content`/`contentRaw`), and `BlogSearchOptions` (`categories: { name: EntryCategory; count: number }[]`, `years: number[]`, `minDate: string`, `maxDate: string`); verify `npx tsc -p src/tsconfig.app.json --noEmit` compiles it clean (the app tsconfig excludes specs, so the model must compile without test types)
- [ ] 2.2 Implement `normalizeTitle(value: string): string` (NFD diacritic strip + lowercase + whitespace collapse) and `matchesQuery(entry: BlogData, query: string): boolean` (empty/whitespace-only query → true; else every whitespace-split word must be a substring of the normalized title); keep both exported for direct testing
- [ ] 2.3 Implement `applyBlogSearch(entries: BlogData[], criteria: BlogSearchCriteria): BlogSearchResult[]` — pipeline: exclude `hidden` → `matchesQuery` → category AND (`entry.categories` must contain every selected category) → date range on `publishedDate` as inclusive `YYYY-MM-DD` string comparisons (validate bounds with `^\d{4}-\d{2}-\d{2}$`, invalid → unset; swap if `from > to`) → sort by `publishedDate` desc (asc when `sort === 'oldest'`, stable for equal dates) → map to `BlogSearchResult` with `matchedCategories = entry.categories.filter(c => selected.includes(c))`; verify with a quick `node -e` smoke against three synthetic entries covering: hidden excluded, AND words, two-category AND, inclusive bounds, swapped bounds, oldest sort
- [ ] 2.4 Implement `getBlogSearchOptions(entries: BlogData[]): BlogSearchOptions` — from visible entries only: union of `categories` with per-entry counts (count = visible entries carrying the category), alphabetical case-insensitive order; distinct `publishedDate` years descending; `minDate`/`maxDate` = min/max `publishedDate` (expected `2007-01-01` / `2026-12-31` for the current corpus); verify against the corpus facts from task 1.2
- [ ] 2.5 Implement URL (de)serialization: `getBlogSearchCriteria(queryParams: Record<string, unknown>): BlogSearchCriteria` (trim `q`; split `categories` on `,`, keep only values present in the `EntryCategory` type, de-duped; validate `from`/`to` as `YYYY-MM-DD` else null; `sort` ∈ `newest|oldest` else `newest`) and `serializeBlogSearchCriteria(criteria: BlogSearchCriteria): Record<string, string | string[] | null>` (write only non-default values: `q` non-empty after trim, non-empty `categories` as a single comma-joined string, `from`/`to` when set, `sort` only when `oldest`; missing/empty keys map to `null` so `mergeIntoQuery` drops them); verify round-trip manually: serialize → parse returns the same non-default criteria, and a fully-default criteria serializes to `{}`
- [ ] 2.6 Write `src/app/pages/blog/blog-search.model.spec.ts` covering at minimum (per the spec delta "Test coverage" requirement): case- and diacritic-insensitive match (use synthetic entries incl. `traéfik`/`Traefik`), AND multi-word, empty query, word appearing only in body does not match (pass an entry with a distinctive `title` and verify `matchesQuery` never consults `content`), category AND semantics + unselect-all restores, date bound inclusivity (boundary-day entries), invalid date ignored, `from > to` swap, out-of-span clamp, hidden exclusion, newest + oldest ordering, options derivation (counts, no unused categories such as `Android`/`Travel`/`Reading`, years descending), param round-trip incl. default-criteria → empty object; run `npm test` and verify all new tests pass on Karma (and on Jest if the `migrate-karma-to-jest` change has landed — both must be green at review time)
